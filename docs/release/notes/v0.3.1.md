## What this release is

The first Signet release signed under notme's current identity format, and
the first verified by a release-verification script that derives the
expected signer from the tag instead of hard-coding it.

Verify a download from a clean machine, with **cosign 3.1.3 or later**:

```
task verify-release TAG=v0.3.1
```

That fetches the trust anchor from the authority's
`/.well-known/ca-bundle.pem`, checks every artifact's SHA-256, and verifies
each signature bundle against the identity of this tag's release workflow.

## What changed for verifiers

- **Signing identity.** Certificates now carry
  `wimse://notme.bot/principal/<percent-encoded OIDC subject>`, for this tag
  `wimse://notme.bot/principal/repo%3Aagentic-research%2Fsignet%3Aref%3Arefs%2Ftags%2Fv0.3.1`.
  The identity names the tag, so a certificate minted for any other tag or
  any branch does not verify. Releases up to v0.3.0 carry the older
  `wimse://notme.bot/gha/agentic-research/signet`; `verify_release.sh`
  accepts exactly that older identity too, so they still verify.
- **cosign 3.1.3 or later is required.** Older cosign can report
  "Verified OK" for a substituted legacy-format bundle
  (GHSA-fx35-mq7g-6g98). `verify_release.sh` refuses older cosign and any
  bundle that is not a Sigstore protobuf bundle.
- `cosign verify-blob` is now documented with `--allow-certificate-chain`,
  which cosign 3.1.3+ needs for bundles that carry a certificate chain.
  This release's bundles carry a single certificate.

## Known limitations — read before depending on this

**Two documented commands are non-functional against the default authority
(`https://auth.notme.bot`).** Both endpoints return **404** in production
(re-checked 2026-10-28):

| Command                                  | Endpoint                  | Status           |
| ---------------------------------------- | ------------------------- | ---------------- |
| `signet authority exchange-github-token` | `POST /exchange-token`    | 404 — not served |
| `signet auth register`                   | `POST /api/cert/register` | 404 — not served |

CI/CD signing, the path this release is signed through, is unaffected. If you
need either command, run your own authority (`signet authority`) or point
`SIGNET_AUTHORITY_URL` at one that serves those routes.

**`signet authority setup-resign` configures a workflow that does not
currently work.** `signet-resign.yml` reads outputs the identity workflow no
longer provides (signet-e6cbea), so post-merge re-signing is not functional.

**What the signatures prove.** They establish that these artifacts were
produced by this repository's release workflow on this tag and have not been
altered since. They are not a statement about the authority's access
controls.
