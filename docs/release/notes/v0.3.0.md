## What this release is

The first Signet release whose artifacts are **cryptographically signed by
Signet itself**. Every binary and the checksum file carry a Sigstore bundle
issued to this repository's GitHub Actions OIDC identity, signed by a
five-minute certificate whose private key never left the runner's memory.

Verify a download from a clean machine — no trust in this page required:

```
task verify-release TAG=v0.3.0
```

That fetches the trust anchor independently from the authority's
`/.well-known/ca-bundle.pem`, checks the SHA-256 of every artifact, and
verifies each signature bundle against the pinned signing identity. It fails
loudly rather than skipping an artifact it cannot check.

## Known limitations — read before depending on this

**Two documented commands are non-functional against the default authority
(`https://auth.notme.bot`).** Both endpoints return **404** in production:

| Command | Endpoint | Status |
|---|---|---|
| `signet authority exchange-github-token` | `POST /exchange-token` | 404 — not served |
| `signet auth register` | `POST /api/cert/register` | 404 — not served |

The authority's discovery document advertises `github_actions_oidc` and
`dpop` grants only. CI/CD signing — the path this release's own artifacts are
signed through — is unaffected and exercised on every release. If you need
either command, run your own authority (`signet authority`) or pin
`SIGNET_AUTHORITY_URL` at one that serves those routes.

**What the signatures do and do not prove.** They establish that these
artifacts were produced by this repository's release workflow and have not
been altered since. They are not a statement about the authority's
operational posture: the production authority's rate limiters are declared
but not bound to enforcement, and registration to the CA is effectively open.
Treat the signing identity, not the authority's access controls, as the thing
being attested.

**Every release publishes as a GitHub prerelease and never self-promotes to
"latest".** That is permanent, not a first-release quirk — production status
is an explicit human step taken only after `task verify-release` passes from
a clean machine. A release still marked "Pre-release" has not completed
promotion.
